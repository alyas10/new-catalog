Для указанного варианта задания необходимо нарисовать UML-диаграмму классов реализуемой программы и разработать консольное приложение на языке C# (см примечания).

**Вариант 1**\
*Тема: Магазин детских игрушек*

1. **Паттерн Builder** -- Реализуйте систему сборки комплекта игрушек для подарка. Пользователь пошагово выбирает: тип игрушки (мягкая, деревянная, электронная), упаковку (базовая, премиум, с лентой), сопутствующие предметы (открытка, сладости, бирка с именем). Builder позволяет создавать разные комплекты (например, «День рождения» или «Новый год») без создания множества конструкторов.

2. **Паттерн Abstract Factory** -- Реализуйте фабрику поставщиков игрушек: три поставщика -- «Игрушки-Мир», «Мягкие Клубки», «Деревянные Сказки». Каждый поставщик производит свои версии игрушек: мягкие, деревянные, пластиковые. При выборе поставщика система автоматически создает игрушки соответствующего стиля и качества.

3. **Паттерн Prototype** -- Реализуйте возможность копирования шаблонных подарочных наборов. Пользователь создает один набор (например, «Мягкий медведь + открытка + шоколадка»), а затем может быстро клонировать его для других детей, меняя только имя ребенка и цвет упаковки.

**Вариант 2**\
*Тема: Система управления библиотекой*

1. **Паттерн Factory Method** -- Реализуйте создание разных типов документов: Книга, Журнал, Газета. Каждый тип имеет уникальные поля (для книги -- автор и издательство, для журнала -- номер выпуска и тема, для газеты -- дата и раздел). Фабричный метод в классе `LibraryManager` отвечает за создание нужного типа документа по запросу пользователя.

2. **Паттерн Builder** -- Реализуйте сборку "читательского профиля": пользователь пошагово указывает: возраст, любимый жанр, частота посещений, предпочтения по формату (бумажный/электронный). Builder позволяет создавать сложные профили без перегрузки конструкторов.

3. **Паттерн Singleton** -- Реализуйте единый журнал учета выданных книг. Всё приложение должно обращаться к одному экземпляру журнала, который хранит историю выдачи, возвращает статистику и не позволяет создавать несколько журналов одновременно.

**Вариант 3**\
*Тема: Система заказа пиццы*

1. **Паттерн Abstract Factory** -- Реализуйте три фабрики пицц: «Итальянская», «Американская», «Веганская». Каждая фабрика создает свои версии теста, соуса, сыра и начинок. При выборе стиля пиццы система автоматически подбирает совместимые ингредиенты (например, веганская фабрика не использует сыр из молока).

2. **Паттерн Builder** -- Реализуйте пошаговое создание кастомной пиццы: пользователь выбирает размер, толщину теста, соус, количество видов начинки, добавки (чеснок, оливки, базилик). Builder позволяет собирать пиццу любой сложности, сохраняя логику сборки.

3. **Паттерн Prototype** -- Реализуйте сохранение популярных комбинаций пицц как шаблонов (например, «Пепперони классика»). Пользователь может выбрать шаблон и быстро создать его копию с изменением одного параметра (например, размера или добавления сыра).

**Вариант 4**\
*Тема: Система управления школьными заданиями*

1. **Паттерн Factory Method** -- Реализуйте создание разных типов домашних заданий: Математическая задача, Эссе, Лабораторная работа. Каждый тип имеет свои обязательные поля (для задачи -- номер варианта и условие, для эссе -- тема и объем, для лабораторной -- цель и оборудование). Фабрика в классе `HomeworkManager` создает объекты по типу, указанному пользователем.

2. **Паттерн Builder** -- Реализуйте сборку "планов подготовки к экзамену": пользователь выбирает дисциплину, количество часов, тип занятий (теория, практика, тесты), дополнительные материалы (видео, шпаргалки, задачи). Builder позволяет формировать сложные учебные планы пошагово.

3. **Паттерн Singleton** -- Реализуйте единый архив успеваемости. Всё приложение работает с одним экземпляром архива, который хранит оценки, посещаемость и комментарии преподавателя. Невозможно создать второй архив -- все данные синхронизированы.

**Вариант 5**\
*Тема: Система оформления подарков*

1. **Паттерн Abstract Factory** -- Реализуйте три фабрики подарков: «Для ребенка», «Для взрослого», «Для коллеги». Каждая фабрика создает свои комплекты: упаковка, открытка, подарок (игрушка, книга, чай). Фабрика гарантирует, что подарок для коллеги не будет содержать игрушку, а для ребенка -- не будет содержать алкоголь.

2. **Паттерн Builder** -- Реализуйте пошаговое создание подарочного набора: выберите упаковку -> выберите подарок -> добавьте открытку -> выберите ленту -> добавьте сувенир. Builder позволяет собирать наборы любой сложности без перегрузки конструкторов.

3. **Паттерн Prototype** -- Реализуйте копирование ранее созданных наборов. Пользователь создал «Подарок на 8 марта» с цветами и шоколадом -- теперь он может клонировать его для подруги, заменив только имя на открытке.

**Вариант 6**\
*Тема: Система настройки компьютера для игр*

1. **Паттерн Builder** -- Реализуйте сборку игрового ПК: пользователь выбирает пошагово -- процессор, видеокарту, оперативную память, корпус, кулер, блок питания. Builder позволяет создавать конфигурации «Эконом», «Средний», «Топовый» без дублирования кода.

2. **Паттерн Abstract Factory** -- Реализуйте три фабрики комплектующих: «Российские», «Китайские», «Европейские». Каждая фабрика производит свои версии компонентов (например, китайская фабрика даёт дешёвые, но надёжные кулеры, европейская -- дорогие, но тихие). При выборе региона система автоматически подбирает совместимые компоненты.

3. **Паттерн Singleton** -- Реализуйте единый менеджер настроек производительности. Все части программы (игровой лаунчер, мониторинг температуры, оптимизатор) обращаются к одному экземпляру, который хранит текущие настройки и не позволяет их дублировать.

**Вариант 7**\
*Тема: Система управления электронной почтой*

1. **Паттерн Factory Method** -- Реализуйте создание разных типов писем: Личное, Рабочее, Спам. Каждый тип имеет свои обязательные поля: для личного -- адресат и приветствие, для рабочего -- тема и срок ответа, для спама -- рекламный баннер и ссылка. Фабрика в классе `EmailCreator` создает нужный тип по выбору пользователя.

2. **Паттерн Prototype** -- Реализуйте шаблоны часто используемых писем. Пользователь создает одно письмо (например, «Запрос на отпуск») и сохраняет его как прототип. Далее он может быстро копировать его, меняя только дату и имя получателя.

3. **Паттерн Abstract Factory** -- Реализуйте три фабрики стилей оформления писем: «Формальный», «Дружеский», «Бизнес». Каждая фабрика создает свои версии шрифтов, цветов, структуры письма и подписей. При выборе стиля все письма автоматически оформляются в соответствии с ним.

**Вариант 8**\
*Тема: Система создания персонажей в игре*

1. **Паттерн Abstract Factory** -- Реализуйте три фабрики рас: «Эльф», «Гном», «Человек». Каждая фабрика создаёт комплекты: оружие, броня, способности, голос. Например, эльфы получают луки и лёгкую броню, гномы -- топоры и тяжёлую броню.

2. **Паттерн Builder** -- Реализуйте пошаговое создание персонажа: выберите расу -> выберите класс -> выберите внешность -> настройте характеристики (сила, ловкость, магия). Builder позволяет собирать сложные персонажи с десятками параметров.

3. **Паттерн Prototype** -- Реализуйте возможность клонирования уже созданных персонажей. Пользователь создал «Эльфа-лучника с зелёной бронёй» -- теперь он может клонировать его, чтобы создать команду, меняя только имя и уровень.

**Вариант 9**\
*Тема: Система управления заказами в кафе*

1. **Паттерн Factory Method** -- Реализуйте создание разных типов заказов: Напиток, Блюдо, Десерт. Каждый тип имеет свои поля: для напитка -- температура и объём, для блюда -- ингредиенты и время приготовления, для десерта -- торт/пирожное и украшение. Фабрика в классе `OrderFactory` создаёт нужный тип.

2. **Паттерн Builder** -- Реализуйте сборку комплексного обеда: выберите блюдо -> выберите напиток -> выберите десерт -> добавьте салат -> выберите соус. Builder позволяет создавать полные наборы, а не отдельные позиции.

3. **Паттерн Singleton** -- Реализуйте единый журнал заказов. Все кассы и кухня работают с одним экземпляром журнала, который хранит все заказы, их статус и историю. Невозможно создать второй журнал -- все данные синхронизированы.

**Вариант 10**\
*Тема: Система оформления документов в офисе*

1. **Паттерн Abstract Factory** -- Реализуйте три фабрики документов: «Финансовый отдел», «Кадровый отдел», «Отдел закупок». Каждая фабрика создаёт свои типы документов: для финансового -- счёт, акт, накладная; для кадрового -- приказ, заявление, трудовой договор; для закупок -- запрос, спецификация, договор поставки.

2. **Паттерн Builder** -- Реализуйте пошаговое создание сложного документа: выберите тип -> введите номер -> введите дату -> добавьте подписи -> добавьте приложения -> выберите шаблон оформления. Builder позволяет собирать документы с десятками полей без перегрузки конструкторов.

3. **Паттерн Prototype** -- Реализуйте копирование шаблонов документов. Пользователь создал «Заявление на отпуск» с определёнными данными -- теперь он может клонировать его для другого сотрудника, меняя только ФИО и даты.

**Вариант 11**\
*Тема: Система создания учебных курсов*

1. **Паттерн Factory Method** -- Реализуйте создание разных типов курсов: Онлайн-курс, Офлайн-семинар, Гибридный курс. Каждый тип имеет свои поля: для онлайн -- ссылка, платформа, доступ; для оффлайн -- аудитория, дата, преподаватель; для гибридного -- оба типа. Фабрика в классе `CourseFactory` создаёт нужный тип.

2. **Паттерн Builder** -- Реализуйте сборку структуры курса: выберите тип -> добавьте модули -> добавьте задания -> добавьте тесты -> добавьте материалы. Builder позволяет создавать сложные курсы пошагово, не перегружая конструктор.

3. **Паттерн Singleton** -- Реализуйте единый архив всех курсов. Все преподаватели и студенты работают с одним экземпляром архива, который хранит список курсов, их статус и доступ. Невозможно создать второй архив -- все изменения синхронизированы.

**Вариант 12**\
*Тема: Система создания персонализированных тренажёров*

1. **Паттерн Abstract Factory** -- Реализуйте три фабрики тренажёров: «Для спортсменов», «Для пенсионеров», «Для детей». Каждая фабрика создаёт свои типы упражнений, режимы, интенсивность и безопасность. Например, для детей -- игра-тренажёр, для пенсионеров -- медленные движения с поддержкой.

2. **Паттерн Builder** -- Реализуйте пошаговое создание программы тренировок: выберите цель (похудение, набор массы, реабилитация) -> выберите длительность -> выберите частоту -> добавьте упражнения -> добавьте рекомендации. Builder позволяет собирать сложные программы без дублирования кода.

3. **Паттерн Prototype** -- Реализуйте копирование шаблонных программ. Пользователь создал «Программу для похудения на 30 дней» -- теперь он может клонировать её для другого пользователя, меняя только вес, возраст и цели.
